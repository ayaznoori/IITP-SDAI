## Session Opening (8 min)

**[Script:]** "Every major tech company is figuring out AI-assisted development. **GitHub Copilot**, **Cursor**, **Claude** — the tools vary. The skill that does not vary is **engineering judgment**. Today you learn to use AI like a senior developer: clear asks, careful review, small verified steps."

## Why Does This Matter?

| Without hygiene | With hygiene |
|-----------------|--------------|
| 200-line mystery diff | 10-line reviewed fix |
| Invented `fetchMoonData()` API | Stuck to taught `fetch` |
| Secrets in suggested `.env` | Rejected before commit |
| "AI broke my project" | AI saved 20 minutes on boilerplate |

> **In the Real World:** **Shopify** engineers report AI speeds scaffolding but **human review** remains mandatory for merge. Your Masai capstone will expect you to explain every line — AI does not remove that bar.

**Interview angle:** "How do you use AI?" Strong answer: small tasks, read diffs, test, Git commits, reject when wrong.

## What Is the Concept?

### Tool Setup Walkthrough

1. Install Cursor / Claude Code
2. Open project folder (portfolio)
3. Open `app.js` and chat panel
4. First prompt: "Explain this file in 3 bullets for a beginner"

**[Script:]** "If the explanation is wrong, you caught your first AI mistake. Good — that is the job."

### Prompt Anatomy (Board)

```
ROLE (optional): You are a patient JS tutor.
INTENT: Fix counter increment bug.
CONTEXT: app.js lines 12-20, button id=countBtn.
CONSTRAINTS: No libraries. Beginner DOM only.
OUTPUT: Show fix only, max 10 lines changed.
```

### Review Checklist (Poster on slide)

1. Correct file and problem?
2. Understand every line?
3. No secrets / no banned deps?
4. Scope creep?
5. Tested locally?

### Reject Examples (Live)

Show AI suggesting entire React rewrite for HTML homework — **Reject.** Narrow prompt.

Show AI adding `innerHTML` with user input — **Reject.** Security risk preview.

### Small-Diff + Git Loop

```
prompt → review → accept → npm/browser test → git commit -m "Fix counter via AI-assisted patch"
```

> **In the Real World:** Small PRs get faster review at **Razorpay**-scale teams. Same logic applies to AI diffs on your laptop.

## How Do We Apply It?

### LO 1: Set up tool for first coding task

**Task:** Add JSDoc-style comment above `addEventListener` block explaining what it does.

**Verify:** Comment accurate? If not — correct manually, note AI error.

---

### LO 2: Write clear prompt with intent and constraints

**Exercise:** Pairs write two prompts for same bug — weak vs strong. Class votes which gets better AI result.

**Real scenario:** Contact form submits with empty email — validate before alert.

---

### LO 3: Review AI output before using

**Live:** Generate fix, pause **before** accept — 3-minute silent line-by-line review, then discuss.

---

### LO 4: Reject unsafe or incorrect suggestions

**Scenarios on slides:**
- Suggests storing API key in frontend JS → **Reject**
- Deletes CSS file "to simplify" → **Reject**
- Uses `eval(userInput)` → **Reject**

---

### LO 5: Small-diff habit

**Cap:** Maximum 15 lines changed per prompt this session. Mentor checks `git diff` stat.

---

## Hygiene Audit (10 min)

Pairs exchange screens — one AI-generated diff, partner runs checklist aloud.

---

## Lecture Summary

- **AI tools accelerate** scaffolding, not responsibility
- **Strong prompts** specify intent, context, constraints, output shape
- **Review** every suggestion like a PR from a junior
- **Reject** scope creep, unsafe patterns, and nonsense APIs
- **Small diffs + Git commits** keep you in control
- **Practical value:** This is how professionals use AI in 2026 without becoming dependent or dangerous

**[Script:]** "Tomorrow: React. You may use Cursor to scaffold — but you will explain every component and prop in class. AI is your pair, not your replacement."
